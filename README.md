# 奶蛙混淆

在浏览器中把原图处理成奶蛙混淆图，并从混淆图中还原处理后的原图。文件只在本机处理，不会上传到服务器；页面不依赖第三方前端库。

## 启动与使用

在仓库根目录运行 `python -m http.server 4173`，然后打开 <http://127.0.0.1:4173/>。

打开“混淆图像”，添加原图并选一个预设，再点“生成混淆图”。可一次选择多张图片，也可以之后继续添加。列表中每张图片都有独立进度、移除和下载操作；批量设置可选择由所有图片共用，或分别调整。

桌面页面会先显示上传、预设和常用设置，生成后再显示预览。手机页面会在开始生成后滚动到预览，并将下载按钮固定在预览工具栏。预览可适应窗口或按原始像素显示；放大后可用滚轮缩放、鼠标拖动，或在触屏上单指拖动画面。

GIF 原图可搭配内置或自定义 GIF 预设。生成的动画保留原图帧数，并按预设动画的播放进度匹配画面；播放速度和循环方式沿用预设。若使用静态预设，则沿用原 GIF 的播放速度和循环方式。静态原图也可以搭配 GIF 预设，生成随预设播放的动画；还原时会取回原始静态文件。

混淆 GIF 的每帧都用预设颜色重新绘制。原始文件会保存在 GIF 内部供还原使用，标准播放器会忽略这部分数据，因此 GIF 和静态原图都能逐字节还原。GIF 不使用 JPG 质量设置，也不提供压缩前 PNG。为控制处理时间和内存，输出帧的最长边不超过 384 px，动画不超过 300 帧。页面会显示 GIF 文件大小和预设相似度。

“所有图片共用设置”默认开启。修改预设、输出质量、预设图案细节、尺寸或高级参数时，整批图片会一起更新。关闭后，每张图片可以单独设置；切换图片时会显示它自己的设置和预览。重新开启时，当前图片的设置会应用到整批。新添加的图片沿用当前设置；修改设置后，已生成的图片会自动重新处理。

“生成全部混淆图”和“还原全部图像”会处理列表中的所有图片。可单独下载当前结果、点击列表中的下载按钮，或将已完成的结果打包为 ZIP。下载文件会保留原文件名；ZIP 中的重名文件会自动编号。单张图片失败不会影响其他图片，失败原因会显示在列表中。还原时选择混淆图即可，不需要预设或手动设置参数。

自定义预设支持透明背景，并会保持原图比例；最长边超过 1536 px 时会先缩小。预设保存在当前浏览器，刷新页面后仍可使用，并会记住上次选择。同一张图片不会重复添加；点击预设缩略图上的「×」可删除，删除提示中可以撤销。预设只保存在当前浏览器和站点中，清除站点数据也会一并清除。还原时不需要原预设。可用方向键切换预设，也可将图片文件拖到对应的上传区域。

常用设置有三个滑条：

- **JPG 质量**：默认 75%，范围 50%–95%。调节后会自动更新混淆图、文件大小和 JPG 还原效果，不用重新点击生成。数值越低，文件通常越小。
- **效果偏向**：向左调，还原图会保留更多原图细节；向右调，混淆图会更像所选预设。中间值兼顾两种效果。调整后会自动重新生成。
- **预设图案细节**：选择混淆图中预设图案的清晰程度。调细后图案更清楚，但文件会更大、处理也更慢。生成后修改会自动重新处理。

静态图片默认下载 **JPG**。页面显示的是最终文件的实际大小，预览和还原检查也使用同一份 JPG。连续调整设置时，只会保留最后一次结果。若 JPG 压缩后无法还原，程序会自动尝试增强保护；仍然失败时会提示提高 JPG 质量，但生成的文件仍可下载。还原不需要密码。

**高级设置**默认收起。可关闭自动缩放并手动设置处理尺寸。混淆图放大倍数默认根据预设图案细节自动选择；关闭自动选择后，可手动选 1–8 倍，每次调整 0.5 倍。分块较细时，倍率过低可能无法生成。还可调整混淆图颜色、原图细节保留程度、JPG 耐压缩程度，以及预设图的显示方式。预设图可完整显示、居中裁切或拉伸。高级区会显示实际参数和相似度，也可另存压缩前的 PNG。

默认会按比例调整处理尺寸：小图放大到短边 1024 px，大图缩小到最长边 2960 px；已在此范围内的图片保持原尺寸。对于长宽比超过约 2.89:1 的图片，系统优先限制最长边，不会裁切或拉伸。放大倍数较高时，还会进一步缩小原图以限制输出像素数。高级设置允许手动缩放 1%–1600%，每次都从上传的原图重新采样，不会反复缩放。手动处理尺寸最多 1600 万像素、单边 16384 px，混淆图最多 3200 万像素。这里的处理尺寸指原图和还原图；混淆图还会按设定放大并补齐网格。

默认按处理图的 **8×8 像素**划分图块，并将混淆图放大 **2 倍**。图块会在整张图中匹配和重排；特别长的图片会分段处理，每段分别重排。图块越小、放大倍数越高，输出文件和处理量通常越大。自动缩放会为输出预留空间；手动设置超出上限时，页面会提示调整尺寸或放大倍数。低质量 JPG 会自动加强保护。还原图的尺寸与处理图一致：缩小原图时丢失的细节无法恢复，放大也不会增加原图没有的细节。

预设默认按比例完整显示，空白处用**透明像素**居中填充；高级预览会保留预设原有的透明部分。也可以改为居中裁切或拉伸。原图长宽比超过 3:1 时，会沿长边切成多个区域，分别匹配同一预设，再合并为一张混淆图。还原时会自动识别并拼接这些区域，不需要额外文件或手动设置。

JPG 不支持透明背景。原图和预设中的透明部分在混淆计算及 JPG 导出时都会铺成白色，因此还原图也会是白底，**不会保留透明通道**。这些留白区域仍用于保存还原所需的信息，不能从 JPG 中删除。JPEG 对照测试也统一使用白底。

GIF 使用 8 位调色板索引记录颜色映射。输出优先沿用 GIF 预设的全局调色板，再从各帧补足颜色。原始文件会先尝试 gzip 压缩；若压缩后反而更大，则直接保存原始字节，避免 GIF 文件无谓增大。

## 算法

图片由 Worker 队列处理。队列会参考 CPU、浏览器报告的可用内存和图片尺寸，最多并行处理 4 张；手机通常最多处理 2 张，大图会进一步限流。移除图片或修改设置时，旧任务会停止。并行主要缩短批量处理时间，实际速度仍取决于设备和图片大小。

还原时只计算用于读取坐标的 DCT 系数，并利用对称性减少运算。RS 和 CRC 使用查表计算。常见放大倍数会从逐块缓存中直接拼出还原图，避免额外创建整张放大图；其他倍率仍沿用旧的整网格采样方式，以保证旧文件边缘像素一致。SSIM 的计算范围和窗口定义保持不变。

混淆、JPG 导出、JPG 还原检查和相似度计算在同一个 Worker 中完成。系统会暂存最近生成的未压缩图像，调整 JPG 质量时优先复用；只有用户另存 PNG 时才进行 PNG 编码。批量预览以压缩格式保存，减少大图占用的内存。文件格式写入 v6，并可读取 v5 和 v6。

- 原图按 2–16 像素的方块划分，再按亮度和颜色匹配预设。颜色相同的预设方块会打散排列，避免原图较浅的方块集中在一处形成白条。边缘不足整块时会复制像素补齐；还原时依据文件头记录的尺寸裁掉补齐部分。
- 颜色适配会在保留原图颜色范围的同时，让方块颜色接近预设。可保留 100%、75%、50% 或 25% 的方块内对比度。原图方块的平均 RGB 颜色以每通道 6 位记录，还原时会用于校正颜色和对比度，减轻 JPG 压缩和图案纹理带来的偏差。
- 坐标使用全图交织的 RS(255,159) 纠错码保存，每个码字最多可修复 48 个错误字节。坐标和颜色数据写入 JPEG 亮度频率，步长会按 JPEG 量化表调整。v6 将文件头和数据均匀分布到整张图上；处理图短边不足 64 px 时，载体至少放大 3 倍，减少信息过密。
- 载体支持 1–8 倍放大，每次调整 0.5 倍，并补齐到完整的 8 px JPEG 网格。放大倍数和分块大小会写入文件头，供还原时读取。图块越细，需要记录的坐标和颜色数据越多；提高放大倍数能留出更多空间，但会增加文件和处理量。
- 文件会记录每个方块在原图中的位置。长图分段处理时，各段分别记录位置；还原会根据文件头自动拼回。只有文件头、数据校验和方块排列检查全部通过后，程序才会还原图像。无需原图、原文件元数据或单独的坐标文件。当前写入 v6，可读取 v5 和 v6；更早的实验格式不支持。

颜色适配和 JPEG 压缩会带来像素误差；另存 PNG 不会消除生成时已经产生的误差。社交平台缩放、裁切或重采样后，坐标可能无法读取。透明通道保留和 WebP 的耐压缩性尚未验证。

## 测试指标

测试会同时检查 **JPG 文件大小、还原图与原图的 SSIM、混淆图与预设的相似度**。直接把原图保存为 JPEG，作为文件大小和画质的对照。

评测会先逐张检查预设相似度是否达标、坐标能否还原，再从符合条件的参数中筛选候选。文件越小、还原 SSIM 越高、最差样本的预设相似度越高，结果越好。测试门槛只用于标记报告中的候选，不会限制页面下载。

不同尺寸下的 SSIM 不能直接比较。评测使用以下固定算法：

| 指标 | 计算方法 | 用途 |
|---|---|---|
| 恢复 SSIM | 最长边约 512 px 面积平均，亮度通道 | 恢复画质，失败记 0 |
| 预设轮廓相似度 | 最长边约 64 px 面积平均，RGB 三通道 SSIM 平均 | 看轮廓与颜色；门槛默认 0.50，逐样本检查 |
| 预设细节相似度 | 最长边约 512 px 面积平均，RGB 三通道 SSIM 平均 | 同时报出细节，防止只看缩小后的效果 |
| JPEG 体积比例 | 全部输出字节 / 输入文件字节 | 含载体放大、坐标及边缘补齐的代价 |

SSIM 使用互不重叠的 8×8 局部窗口，并非标准的全分辨率高斯窗口算法。相似度门槛只用于实验筛选，不保证任意图片都能达到。纹理、颜色、尺寸、长宽比和透明区域都会影响结果。

评测工具只供本地开发使用，不会出现在图片处理页面中。运行 `tests/benchmark.mjs` 会生成逐图数据、曲线、表格和 CSV，可按参数筛选，并查看每张图片的最低预设相似度和还原成功率。

## 批量实验

运行算法和边界测试：

```powershell
node tests/selftest.mjs
node tests/gif-selftest.mjs
```

命令行批量评测需要安装 FFmpeg。通常先用缩小图片筛选参数，再用原始尺寸复测入选配置：

```powershell
node --expose-gc tests/benchmark.mjs --count=4 --tiles=8 --scales=2,3 --steps=16,24 --gains=0.5,0.75 --presets=0,1,2,3 --max-side=768 --report=screening-new
node --expose-gc tests/benchmark.mjs --count=4 --profiles=2:16:0.5,2:16:0.75,3:16:0.75,3:24:0.75 --presets=0,1,2,3 --report=native-final-new
```

可用 `--qualities=95,85,75,65,55`、`--threshold=0.5`、`--fit=contain|cover|stretch`、`--color-adapt=no`、`--color-gain=0.75` 和 `--edges=no` 设置评测参数。`--profiles=倍率:强度:细节保留,...` 可只测试指定配置。添加 `--background` 可在后台运行并保存日志；`--count` 用来设置测试图片数量。缩图评测以缩小后 JPEG-95 的文件大小为基准，报告会标明这一点；此结果不能与原始分辨率直接比较。

评测结果保存在 `reports/`。JSON 和 CSV 保存详细数据及汇总；HTML 页面可筛选合格配置；两张 SVG 曲线可单独查看或分享。FFmpeg 的 95/85/75/65/55 档分别使用 `mjpeg -q:v 2/3/5/7/10` 和 `yuvj420p`，与浏览器的 JPEG 质量值并不等价。

启动本地服务器后运行 `node tests/browser-smoke.mjs`，可检查默认和高级设置、图片生成与还原、预览缩放和平移、文件下载、预设保存、动画处理和不同屏幕宽度下的页面布局。测试还会检查 JPG 文件大小、GIF 逐字节还原、批量处理和 ZIP 文件内容。添加 `--reports` 可一并检查交互式评测页面；添加 `--background` 可在后台运行。测试图片位于 `test/static/` 和 `test/animated/`。

`node tests/zip-selftest.mjs` 会调用 Python 标准 ZIP 读取器，检查中文文件名、重名编号、CRC、日期和文件内容。

`node tests/compatibility.mjs` 会对照旧提交，检查普通和半倍放大、奇数分块、长窄图及旧 32 px 参数生成的文件能否还原为相同像素，并比较新文件的还原 SSIM。

性能测试命令：

```powershell
node --expose-gc tests/performance-compare.mjs --max-side=1920
node tests/browser-performance.mjs --background
```

第一个脚本从 Git 读取 `b5d2b4f` 版本作为基准，在相同图片上比较耗时、像素差异、旧文件兼容性和新 JPG 的还原 SSIM。第二个脚本比较浏览器中的完整生成与还原流程、单独还原，以及四张图片串行和并行处理的耗时。结果保存在 `.test-artifacts/performance/`。单独还原的新版计时包含 PNG 导出，旧版计时只包含生成像素；完整流程都包含 JPG 还原检查。性能测试期间不要同时运行其他批量任务，以免 CPU 和内存占用影响结果。

实测数据和主要耗时来源见[批量处理与性能验证](PERFORMANCE.md)。四张默认尺寸的大图平均处理时间为 17.4 秒降至 8.9 秒，还原画质评分不变；四张约 1536×864 的图片并行处理时间为 11.6 秒降至 4.8 秒。以上是开发机实测，不代表其他设备的速度。

用四张测试图片检查默认设置的处理时间和 JPG 效果：

```powershell
node tests/performance-samples.mjs --max-side=768
```

脚本会输出每张图片的处理时间、JPG 还原状态、还原 SSIM 和预设相似度。调整 `--max-side` 可快速测试缩图；需要检查完整的压缩效果时，运行上面的批量评测。

临时测试文件保存在仓库的 **`.test-artifacts/`** 目录中：浏览器日志、截图、下载文件和 Chrome 用户目录在 `.test-artifacts/browser/`；批量测试日志在 `.test-artifacts/benchmark/`；1.5 倍对照测试在 `.test-artifacts/compact/`。测试进程的临时目录也指向仓库内部。`.test-artifacts/` 已加入 `.gitignore`，长期报告保存在 `reports/`。

浏览器测试会比较默认设置生成的 JPG 和压缩前 PNG，记录实际文件大小及还原 SSIM，结果保存在 `.test-artifacts/browser/jpg-verification.json`。8 px 分块能呈现更细的预设图案；16 px 分块的还原误差较低。可结合页面中的 JPG 预览选择适合的效果。

`node tests/compact-benchmark.mjs` 会用四张本地测试图片比较 8 px / 2 倍、8 px / 1.5 倍和 16 px / 1.5 倍三种配置。报告中的 `presetSSIM` 是压缩前的预设相似度；最终 JPG 的分数由 `tests/benchmark.mjs` 计算。

例如，使用以下命令测试 4 px 分块：

```powershell
node --expose-gc tests/benchmark.mjs --count=1 --tiles=4 --scales=3,4 --steps=16 --presets=0,2 --qualities=75,65 --max-side=1024 --edges=no --report=fine-tiles
```

已生成的报告见[评测报告目录](reports/index.html)。在[交互比较页](reports/compare.html)可以调整预设外观和还原效果的最低分数，并查找原始分辨率测试中体积最小的合格配置。四张图片的对照见[示例](reports/example.html)；示例图经过缩小，仅供查看，不能用于还原。

## v5 历史测试结果

以下为 v5 的历史结果。v6 已调整默认缩放、长图分段和信息分布，不能直接与这些数据对比。测试使用 3 张照片（1920×1200 一张、2560×1440 两张）和全部 4 个预设，每个配置包含 12 个样本。共测试 8 组配置、384 次 JPEG 压缩和还原。文件体积是按每张原图大小计算后的等权平均值；预设门槛为 0.50，并检查 12 个样本中最低的轮廓相似度。表中所有文件都成功还原。

| 方案（全部按原图 8×8 px 分块） | JPEG 档 | 体积 / 原文件 | 平均恢复 SSIM | 预设轮廓均值 / 最低 | 平均预设细节 |
|---|---:|---:|---:|---:|---:|
| 原尺寸载体，强度 10，75% 细节 | 85 | 192.4% | 0.9511 | 0.6388 / 0.5705 | 0.3250 |
| 2 倍载体，强度 16，75% 细节 | 65 | 178.3% | 0.9528 | 0.8519 / 0.7632 | 0.5785 |
| 2 倍载体，强度 16，50% 细节 | 65 | 158.4% | 0.9149 | 0.9094 / 0.8545 | 0.6939 |
| 3 倍载体，强度 16，75% 细节 | 65 | 269.9% | 0.9864 | 0.8639 / 0.7838 | 0.5828 |
| 3 倍载体，强度 24，75% 细节 | 55 | 236.2% | 0.9752 | 0.8592 / 0.7832 | 0.5882 |

在这批测试中，2 倍放大、强度 16、保留 75% 细节的配置，满足“每张图的预设轮廓 ≥0.50、平均还原 SSIM ≥0.95、全部成功还原”三个条件，且文件体积最小。FFmpeg 质量 95、85、75、65 档均可还原，55 档均失败；失败数据仍保留在曲线中。页面默认使用浏览器生成 JPG，质量为 75%，与 FFmpeg 档位不能直接对应。

此报告以输入原文件大小作为体积基准。PNG 转成 JPG 能节省多少空间，取决于具体图片；页面会显示最终 JPG 的实际大小。测试门槛只用于比较配置，不会限制用户下载。

v6 还测试了 27 个特殊案例，包括透明图片、尺寸不能被分块整除的图片、窄图和三种预设显示方式。PNG、JPEG-95 和 JPEG-75 文件都能成功还原，其中 15 个达到 0.50 的预设相似度门槛。其他案例未达到门槛，因此不计入照片平均值。能成功还原不代表混淆图一定足够像预设。详情见 [edge-cases.csv](reports/edge-cases.csv)。
