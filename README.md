# Naiwa 图像实验室

纯前端的细分块图像混淆与自包含还原工具。图像在浏览器本地处理，没有服务端或第三方前端依赖。

## 启动与使用

在仓库根目录运行 `python -m http.server 4173`，打开 <http://127.0.0.1:4173/>。

上传原图，选择预设，点击“生成混淆图”。普通模式提供两个滑条：

- **JPG 质量**：默认 75%，范围 50%–95%。生成后调节会自动更新混淆预览、实际文件大小和 JPG 还原预览，无需再次点击生成。质量数值越低，通常文件越小。
- **还原偏好**：从还原画质优先到抗压鲁棒优先，默认均衡。应用根据图像尺寸、JPG 质量与偏好选择分块、水印强度和载体倍率；生成后调整会自动重新处理。

默认下载 **JPG**。显示的大小取自最终 JPG 的实际字节数，下载直接使用同一个文件；预览和还原验证也来自这个 JPG。快速连续拖动时只采用最新设置，旧任务不能覆盖最终结果。自动模式会在 JPG 坐标读取失败时尝试提高强度；仍失败时页面提示提高 JPG 质量，文件仍可下载。还原文件无需口令。

**高级模式**默认收起，可查看采用的参数与 SSIM，或开启手动调整分块、载体倍率、颜色适配、预设适配及水印强度，也可另存压缩前 PNG。预设相似度下限仅用于实验候选筛选，**不影响生成或下载**，用户自行通过预览判断效果。JPG 还原 SSIM 与适配后的预设图也在高级模式中提供。

均衡模式通常按原图 **8×8 像素**细分、使用 2 倍载体、75% 块内细节；低质量 JPG 自动提高水印强度。两端偏好会调整强度和载体，较大的载体用于保留更多恢复信息。大图会限制载体像素量，避免不必要的内存开销。恢复后回到原始尺寸。

透明原图和预设统一合成到白底，恢复的是白底可见图，**不保留原透明通道**。JPEG 基线也使用相同白底。预设默认完整显示并留白，可以选择居中裁切或拉伸，预设和原图尺寸无需一致。

`images/animated/` 用于未来对 GIF 每一帧进行混淆。本轮只处理静态图，不运行 GIF 帧处理。

## 算法

- 使用原图 8、16 或 32 像素块，根据平均亮度和对立色进行平衡递归匹配，取代粗网格和 Morton 排序。边缘不再留在原位；不足完整块的边缘复制补齐，头部记录原始尺寸，恢复后裁掉补齐区。短窄图也补齐处理。
- 块级颜色适配在不裁掉原图颜色的范围内，让每块均色向预设靠近，并可选择保留 100%、75% 或 50% 的块内对比度。原块 RGB 均色以每通道 6 位记录，恢复时结合图中实际均色还原颜色与对比度，也减小饱和水印和 JPEG 引起的均色漂移。量化和水印误差会在逆变换中放大，故必须实测恢复 SSIM。
- 全图交织 RS(255,159) 坐标纠错替代每块内重复坐标。每个码字可修复最多 48 个错误字节；坐标与均色载体采用按 JPEG 亮度量化表调整步长的 DCT-QIM，头部单独重复保护。原图短边不足 64 px 时，载体至少放大 3 倍并补齐，避免过密水印。
- 头部 CRC、载荷 CRC 和完整排列校验通过后才还原。无需原图、原文件元数据或外置坐标文件。新版格式不读取早期实验版输出。

颜色适配、坐标水印和 JPEG 会引入像素误差，PNG 保存也不能消除已经写入的水印误差。平台缩放、裁切、重采样可能使坐标无法读取。透明通道保留和 WebP 鲁棒性不在本轮已验证范围。

## 三指标评测与门槛

评测同时考察：**完整 JPEG 体积、恢复图与原图 SSIM、混淆图与适配预设相似度**。JPEG 原图直压仍作为基线。

实验评测先在每个样本上检查相似度门槛和坐标还原，再在满足约束的点中计算三指标 Pareto 候选：体积越小越好、恢复 SSIM 与最差样本的预设相似度越高越好。该门槛只影响实验候选标记，不参与下载按钮的判断。

指标定义保持固定，不能把不同尺度的 SSIM 混为一谈：

| 指标 | 计算方法 | 用途 |
|---|---|---|
| 恢复 SSIM | 最长边约 512 px 面积平均，亮度通道 | 恢复画质，失败记 0 |
| 预设轮廓相似度 | 最长边约 64 px 面积平均，RGB 三通道 SSIM 平均 | 看轮廓与颜色；门槛默认 0.50，逐样本检查 |
| 预设细节相似度 | 最长边约 512 px 面积平均，RGB 三通道 SSIM 平均 | 同时报出细节，防止只看缩小后的效果 |
| JPEG 体积比例 | 全部输出字节 / 输入文件字节 | 含载体放大、坐标及边缘补齐的代价 |

SSIM 使用不重叠的 8×8 局部窗口，不是全分辨率高斯窗口的标准实现。相似度门槛是可检查的实验条件，不代表任意原图都能达标。图像纹理、色彩分布、尺寸、比例与透明区域均会影响结果。

浏览器可以一次运行多组参数，整批结束后统一显示两幅体积曲线、表格与候选，并导出 CSV。曲线空心点表示未达标，实心点表示满足当前样本约束。

## 批量实验

算法及边界自测：

```powershell
node tests/selftest.mjs
```

命令行批量评测需要 FFmpeg。先以缩图做快速筛选，再对选中的配置运行原始尺寸确认：

```powershell
node --expose-gc tests/benchmark.mjs --count=3 --tiles=8 --scales=2,3 --steps=16,24 --gains=0.5,0.75 --presets=0,1,2,3 --max-side=768 --report=screening-new
node --expose-gc tests/benchmark.mjs --count=3 --profiles=2:16:0.5,2:16:0.75,3:16:0.75,3:24:0.75 --presets=0,1,2,3 --report=native-final-new
```

支持 `--qualities=95,85,75,65,55`、`--threshold=0.5`、`--fit=contain|cover|stretch`、`--color-adapt=no`、`--color-gain=0.75`、`--edges=no`。`--profiles=倍率:强度:细节保留,...` 可只运行候选组合。加 `--background` 在后台运行整批任务并保存日志。`--count` 控制测试图片数量；缩图实验以缩图的 JPEG-95 字节数为体积基准，并在报告中明确标注，不能和原始分辨率结果直接比较。

输出保存在 `reports/`：JSON 包含逐图、逐预设、逐配置、逐质量明细和独立透明/窄图案例；CSV 是平均值与最差相似度；HTML 支持过滤达标候选；两幅 SVG 可以独立分享。FFmpeg 标称 95/85/75/65/55 档对应 `mjpeg -q:v 2/3/5/7/10`、`yuvj420p`，和浏览器 JPEG 质量参数不等价。

启动本地服务器后运行 `node tests/browser-smoke.mjs` 可验证普通 / 高级模式、JPG 大小实时更新、快速滑动后的最终结果、实际下载文件字节数、相似度不阻止下载、下载 JPG 的导入还原、偏好滑条自动重新生成、JPEG 评测与手机布局。加 `--reports` 同时验证保存的交互报告，`--background` 可后台运行。

所有临时测试文件都在仓库内的 **`.test-artifacts/`**：浏览器测试日志、截图、下载 JPG、Chrome 用户目录位于 `.test-artifacts/browser/`，批量测试后台日志位于 `.test-artifacts/benchmark/`。测试子进程的 `TEMP`、`TMP`、`TMPDIR` 也指向仓库内目录。该目录已加入 `.gitignore`；长期评测数据仍保存在 `reports/`。不使用用户的系统临时目录。

本次 Chrome 导出验证中，1920×1200 的示例使用均衡自动参数：压缩前 PNG 为 15,229,743 字节，JPG 65% 为 952,267 字节（PNG 的 6.25%）；PNG 还原 SSIM 0.91494，JPG 还原 SSIM 约 0.9143。脚本会将实际下载文件和对比数据保存到 `.test-artifacts/browser/`，其中 `jpg-verification.json` 记录字节数与分数。该数据是此示例的实测结果。

已有批次见 [评测报告目录](reports/index.html)，[交互比较](reports/compare.html) 可以调整预设相似度与恢复 SSIM 门槛，并从所有原始分辨率实测点中查找文件最小的候选。实际四图对照见 [示例](reports/example.html)。示例是缩小后的展示图，不用于解码。

## 已保存的算法基准

原始分辨率验证使用 3 张照片（1920×1200 一张、2560×1440 两张）和全部 4 个预设，每个点包含 12 个样本。最终版共测试 8 组参数、384 次 JPEG 压缩还原。以下体积按原文件字节数逐图计算后等权平均；预设门槛取 12 个样本的最小轮廓分数，门槛为 0.50。表中各点的坐标恢复均为 100%。

| 方案（全部按原图 8×8 px 分块） | JPEG 档 | 体积 / 原文件 | 平均恢复 SSIM | 预设轮廓均值 / 最低 | 平均预设细节 |
|---|---:|---:|---:|---:|---:|
| 原尺寸载体，强度 10，75% 细节 | 85 | 192.4% | 0.9511 | 0.6388 / 0.5705 | 0.3250 |
| 2 倍载体，强度 16，75% 细节 | 65 | 178.3% | 0.9528 | 0.8519 / 0.7632 | 0.5785 |
| 2 倍载体，强度 16，50% 细节 | 65 | 158.4% | 0.9149 | 0.9094 / 0.8545 | 0.6939 |
| 3 倍载体，强度 16，75% 细节 | 65 | 269.9% | 0.9864 | 0.8639 / 0.7838 | 0.5828 |
| 3 倍载体，强度 24，75% 细节 | 55 | 236.2% | 0.9752 | 0.8592 / 0.7832 | 0.5882 |

上述 2 倍载体、强度 16、75% 细节配置，是这批测试在“逐样本预设轮廓 ≥0.50、平均恢复 SSIM ≥0.95、全部坐标恢复”条件下体积最小的已测点。它在 FFmpeg 95、85、75、65 档全部恢复，55 档全部失败；失败点保留在曲线上。当前页面默认导出浏览器 JPG，质量默认 75%，与 FFmpeg 的标称档位不等价。

这批报告的体积基准是输入原文件。PNG 改存 JPG 的体积节省应以每张图的实际文件为准；当前页面直接显示下载 JPG 的大小。三指标报告继续用于算法比较，用户下载不受实验门槛限制。

另有 27 个含透明、非整块尺寸、窄图和三种适配方式的独立案例，PNG/JPEG-95/JPEG-75 全部坐标可读，其中 18 个达到 0.50 相似度门槛。其余案例仍判为不合格，不纳入上述照片平均值；处理成功不等于预设外观达标。明细见 [edge-cases.csv](reports/edge-cases.csv)。
